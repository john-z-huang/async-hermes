## 正文

## 背景

当前 `main.py` 中的 `run_code_agent()` 使用 `Runner.run()` 等待任务结束后一次性返回 `result.final_output`，CLI 也只在运行完成后通过 `print(output)` 输出结果。长任务执行期间没有增量反馈，推理模式开启后也无法区分推理响应与最终内容响应，完整响应不会保存到文件。

## 目标

将 Agent 的响应处理改为流式模式：运行过程中实时输出响应；当 `--enable-reasoning=true` 时，清晰区分推理响应与内容输出响应；并将本次运行的完整响应持久化到 workspace 下的文件，便于后续查看。

## 建议实现

- 将 `Runner.run()` 改为 Agents SDK 支持的流式运行方式（例如 `Runner.run_streamed()`），异步消费响应事件。
- 对流式事件进行分类与增量输出：
  - 内容输出使用明确标识，例如 `[content]` 或独立的 Markdown 区段。
  - 仅在开启推理模式时输出推理事件，并使用不同标识，例如 `[reasoning]`。
  - 不应将工具调用、生命周期事件等误判为正文；如需显示，应使用独立类型标识。
- 在 CLI 中增加输出文件配置（例如 `--output-file`）：
  - 默认路径位于 `--workspace` 指定目录内，例如 `<workspace>/agent-response.md`。
  - 相对路径按 workspace 解析，并遵守 workspace 路径边界；不得写到 workspace 外。
  - 文件内容至少包含本次运行的推理响应（如启用）和内容输出，二者结构清晰、可独立阅读。
  - 保存的内容必须与本次流式输出汇总后的完整响应一致，不能因分片而丢失、重复或乱序。
  - 运行异常或被中断时，应尽可能保留已经接收的响应，并明确标注未完整结束。
- 保持现有 `--enable-reasoning`、`--reason-effect`、`--workspace` 与只读 shell 权限行为兼容。
- 更新 README，说明流式输出格式、推理/正文标识和输出文件的默认路径及覆盖方式。

## 验收标准

- [ ] 启动 Agent 后，正文 token/文本片段会随事件到达实时显示，而不是任务结束后一次性打印。
- [ ] `--enable-reasoning=false` 时只显示内容响应，不出现空的推理区段。
- [ ] `--enable-reasoning=true` 时，推理响应和内容输出响应使用稳定、明确且不同的标识展示。
- [ ] 每次运行结束后，workspace 内存在一个响应文件，包含按正确顺序汇总的完整响应。
- [ ] 可通过 CLI 参数指定输出文件；workspace 外路径会被拒绝并返回清晰错误。
- [ ] 流式分片不会重复打印、遗漏或破坏多字节字符。
- [ ] API/网络异常及用户中断时，已有片段得到保存，并能看出运行未正常完成。
- [ ] `tests/test_main.py` 增加流式事件分类、推理模式开关、文件路径校验、完整持久化和异常/中断场景的测试。
- [ ] 现有测试继续通过，README 已同步更新。
