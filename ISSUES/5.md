## 正文

## 背景

当前 `main.py` 仅支持通过必填的 `--question` 参数执行一次 Agent 请求，输出并保存响应后进程即退出。为了支持交互式连续使用，同时保留现有的一次性调用方式，需要增加可选运行模式参数。

## 需求

新增可选命令行参数：

```text
--running-mode {loop,one-shot}
```

- 默认值：`loop`
- `loop`：程序持续运行，在 `while` 循环中逐轮接收用户输入、发起 Agent 请求并输出本轮结果。
- `one-shot`：仅执行一次请求，沿用当前 `main.py` 的 Agent 调用、流式输出和结果持久化逻辑，完成后退出。

### loop 模式

1. 从标准输入持续读取每一轮问题。
2. 每次收到非空问题后调用 `run_code_agent(...)`，并完整输出该轮结果。
3. 输入 `/exit` 或 `/quit` 时正常退出循环；退出命令不应发送给 Agent。
4. 建议忽略空输入并继续等待下一轮，避免触发当前的非空 `question` 校验错误。
5. 如果启动时传入了 `--question`，将其作为第一轮问题执行，之后继续从标准输入读取；未传入时直接等待交互输入。
6. 整个 loop 会话沿用启动时确定的 `--system-prompt`、`--user-prompt`、`--content`、`--enable-stream-output`、`--enable-reasoning`、`--reason-effect`、`--workspace` 和 `--permissions` 配置；其中 `--user-prompt` 和 `--content` 只作为会话的初始上下文加入一次，不在每轮重复追加。
7. 每轮响应都应按照现有逻辑持久化。未显式传入 `--output-file` 时继续使用响应哈希生成独立文件，避免覆盖；显式传入固定 `--output-file` 时需明确并测试覆盖行为。

#### 多轮上下文的累积与使用

同一次 `loop` 进程中的所有有效输入属于同一个会话。后一轮必须能够使用前面已成功完成轮次的对话和工具结果，而不是把每一轮作为相互独立的 Agent 请求。

1. 第一轮使用 `--user-prompt`、第一轮问题和可选的 `--content` 构造初始输入。`--system-prompt` 作为 Agent instructions 使用，不作为普通用户消息反复写入历史。
2. 每轮成功结束后，保存 Agents SDK 返回的完整结构化输入历史。实现时优先使用 `result.to_input_list()` 或 SDK 提供的等价会话机制，不要仅把终端中显示的最终文本拼接回下一轮提示词。
3. 下一轮从标准输入取得的新问题作为新的 user message 追加到历史末尾，再将累计历史交给 `Runner.run_streamed(...)`。历史应按原始顺序包含：
   - 之前各轮的用户输入；
   - Agent 的内容响应；
   - 为后续推理所需的 reasoning response items；
   - function call、function call output 等工具调用及结果。
4. `--user-prompt` 和 `--content` 是会话级初始上下文，只加入第一轮一次；`--system-prompt`、模型设置、工具、workspace 和 permissions 是进程级配置，在每轮运行时继续生效，但不重复追加到消息历史。
5. 空输入、`/exit` 和 `/quit` 不加入上下文。退出命令只终止当前 loop 会话。
6. 只有成功完成的轮次才更新累计历史。某轮请求失败时，应保留此前成功轮次的历史，不把异常文本或不完整响应写入后续上下文；程序应报告该轮错误并允许用户继续输入。
7. 上下文只在当前进程内存中保持。退出并重新启动后创建新会话；此前持久化的响应文件仅用于查看，不自动加载为新会话上下文。
8. 初始实现保留完整历史，直到达到模型或提供商的上下文窗口限制。本任务不要求自动摘要、裁剪或跨进程恢复；达到限制时应给出清晰错误，不得静默丢弃早期轮次。

例如，第一轮输入“分析项目的测试结构”并得到结果后，第二轮输入“根据刚才的分析，指出最缺少的测试”时，Agent 应能直接引用第一轮的分析和工具结果，无需调用方再次传入这些内容。

### one-shot 模式

1. `--question` 必须为非空值；缺失或为空时给出清晰的命令行错误。
2. 仅发起一次 Agent 请求。
3. 输出、推理显示、流式开关和响应持久化行为与当前实现保持一致。
4. 请求完成后进程正常退出。

## CLI 示例

```bash
# 默认进入持续交互模式
python main.py

# 显式进入持续交互模式
python main.py --running-mode loop

# 将 question 作为 loop 模式的第一轮输入，然后继续交互
python main.py --running-mode loop --question "总结当前项目"

# 仅执行一次并退出
python main.py --running-mode one-shot --question "总结当前项目"
```

## 验收标准

- [ ] `--running-mode` 只接受 `loop` 和 `one-shot`，默认值为 `loop`。
- [ ] `loop` 模式可以连续完成至少两轮输入和输出，且不会在首轮结束后退出。
- [ ] `loop` 模式输入 `/exit` 或 `/quit` 后立即正常退出，且不会调用 Agent。
- [ ] `loop` 模式空输入不会调用 Agent，也不会终止程序。
- [ ] `loop` 模式支持将可选的 `--question` 作为第一轮任务。
- [ ] `loop` 模式的第二轮能够引用第一轮的用户输入、Agent 响应和工具结果，无需调用方重复提供。
- [ ] 每轮成功后通过 `result.to_input_list()` 或等价 SDK 会话机制保留结构化历史，不通过手工拼接终端输出构造上下文。
- [ ] `--user-prompt` 和 `--content` 只进入初始上下文一次，系统提示词和进程级配置不会作为消息在每轮重复累积。
- [ ] 空输入、退出命令和失败轮次不会污染累计上下文；失败后仍可基于此前成功历史继续下一轮。
- [ ] loop 上下文不跨进程自动恢复，响应文件也不会被隐式加载为新会话历史。
- [ ] 增加测试，断言第二次 Agent 调用的输入按顺序包含第一轮结构化历史和第二轮 user message。
- [ ] `one-shot` 模式保持当前单次执行行为，并在执行完成后退出。
- [ ] `one-shot` 模式缺少有效 `--question` 时返回清晰错误。
- [ ] 两种模式均正确支持流式/非流式输出和响应文件持久化。
- [ ] 为参数解析、退出命令、空输入、连续多轮和 one-shot 行为补充自动化测试。
- [ ] README 增加两种运行模式及示例说明。
