# Agent Hermes and Async Batch Task

## 研究背景

当前 Code Agent 在代码生成方面已表现出很强的能力，但在缺少约束时，往往会将任务材料的大量原始内容直接读入上下文。这会带来巨量 Token 消耗，使成本、上下文容量和长期可持续性成为实际限制。

## 研究设想

在 Code Agent 的工作流中引入异步 Batch API：先由 Agent 分析任务材料的结构与处理目标，再编写面向材料处理的提示词，将待处理内容组织为 JSONL 文件并异步提交。这样，Code Agent 的主上下文只保留任务规划、材料结构、提示词与批处理结果摘要，而不必承载大量原始材料。

## 关键流程

* Agent 识别任务目标、输入材料类型与输出结构；  
* Agent 生成适配该任务的提示词，并将材料拆分、整理为 JSONL 请求；  
* 使用 Batch API 异步处理材料；  
* 将批处理结果回收、校验并汇总为精简信息，供 Code Agent 继续决策和执行。

## 预期价值

* 该方案将高容量材料处理与 Code Agent 的主推理过程解耦，减少 Code Agent 上下文中的 Token 消耗；  
* Batch API 可根据具体任务选择显著小于 Code Agent 主模型的模型规模；  
* 在保证材料分析、提取或转换质量满足任务需求的前提下，有望显著降低整体 Token 成本，并提升长任务运行的可持续性。
